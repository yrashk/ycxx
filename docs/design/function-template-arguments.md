# Function pointer and reference template arguments

The template argument keeps its converted type and the symbolic address produced by constant evaluation. The existing `VLvalue` names a `VEntity` and carries the path and byte offset. A function address has an empty path and zero offset. The function entity distinguishes overloads and distinct functions with the same signature. The native relocation uses the same entity, so the template identity and pointer in the body agree. See [temp.arg.nontype], [temp.type], and [expr.const].

The first native slice covers pointer values naming externally linked functions. The object pipeline supplies the mangler with the addressed declaration's source name, scope, signature, language linkage, and any specialization arguments. A C++ name is encoded in the enclosing mangler so the embedded entity shares that name's substitutions. A C linkage name uses its source name without the function signature. The address expression is `XadL_Z<encoding>EE`. A conversion to a potentially throwing pointer records the converted type with `cv` before the address expression, following Clang's encoding and [conv.fctptr]. A null pointer to a C++ function type uses the converted pointer type and zero in an expression primary. Mangling the C-linkage function type itself is tracked in #287. [Itanium C++ ABI §5.1.6](https://itanium-cxx-abi.github.io/cxx-abi/abi.html#mangle.expr).

The reference form uses `L_Z<encoding>E` and retains the selected lvalue. Binding an overloaded name needs the substituted parameter type before constant evaluation. That target type selects the function under [over.over] and allows the existing function-to-pointer conversion or reference binding, as appropriate. The first slice leaves reference binding, target-typed overload selection, and translation-unit-local arguments tracked in [#406](https://github.com/yrashk/ycxx/issues/406).
