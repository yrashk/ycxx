# The C++26 feature map

Every language feature ycxx must support, ranked by age and by how often real code uses it,
with its status on `main` and its issue. Generated by [`tools/feature-map/feature-map`](../tools/feature-map/feature-map) from
[`features.toml`](../tools/feature-map/features.toml); edit that, then run the script. Tracked in [#282](https://github.com/yrashk/ycxx/issues/282).

180 features: 63 done, 36 partial, 81 missing.

## How to read it

- **Feature:** one row per feature a user would name, from the pinned draft's core clauses
  ([lex] to [cpp]) and the library pieces the compiler provides. `feature-map check` fails when
  a core clause of the draft is not covered by some row.
- **Clauses:** stable names in the pinned draft. `[x]*` is the clause and all its subclauses;
  a plain `[x]` is that clause's own text.
- **Std:** the revision the feature first appeared in. Later extensions are their own rows.
- **Uses (projects):** matches of the feature's detector (a regular expression over code with
  comments and literals blanked, in features.toml) over the corpus, and how many of its
  21 projects use it. *core*: every program uses it. *n/m*: not measured (no reliable
  detector); ranked at the median.
- **Draft examples:** of the draft's examples (tests/draft) in clauses only this feature cites,
  how many ycxx passes. An example often needs other features too, so a done feature can have
  failing examples.
- **Status:** on `main`, judged from a probe program (`feature-map probe`), tests/own, the draft
  examples, STATUS.md and the open issues. *partial* means the common case works.
- **#:** the priority rank: older and more used first (`score = usage + age`, see
  tools/feature-map/feature-map).
