# The draft's examples

The working draft's examples as accept/reject tests: the strongest oracle (DECISIONS §5.4) and
the measure of M3. Everything here is generated by [`tools/draft-examples`](../../tools/draft-examples)
(#6) and is regenerated, not edited.

| file | what |
|---|---|
| `PINS` | the pinned commits of the draft's LaTeX sources (cplusplus/draft) and of the CWG issues list (cplusplus/CWG, gh-pages) |
| `<chapter>/<subclause>-<n>.accept.cpp`, `.reject.cpp` | example *n* of the subclause, by its stable name; `temp/temp.deduct.call-3.reject.cpp` |
| `examples.tsv` | every example of the core clauses ([lex]–[except], [cpp], [temp]): its paragraph, LaTeX source line, and test kind, or why it is skipped |
| `oracles.tsv`, `oracle-versions.txt` | Clang 23's and GCC 16's errors on each example, keyed by a hash of its text |
| `DISAGREEMENTS.md` | the tests an oracle gets wrong against the draft, with the CWG issues filed against the subclause |
| `cwg-issues.tsv` | the CWG issues list: each issue's subclause, status, whether it is resolved, and whether the pinned draft still has that subclause |

## How an example becomes a test

- The example's code blocks are joined; LaTeX in comments and `@escapes@` is turned back into text.
- A line whose comment gives an ill-formed verdict ("error", "ill-formed", "ambiguous",
  "access error", ...) gets a `//! error` marker, and the example is a reject test. Otherwise it
  is an accept test. Errors are compared by line, never by column or wording.
- Standard headers the example uses without including (`std::initializer_list`, `typeid`,
  placement `new`) are included at the top, marked `// added by tools/draft-examples`.
- Examples using reflection get `// FLAGS: -freflection`: GCC 16 needs it. Clang 23 has no
  reflection and ignores it.

An example is skipped, with its reason in `examples.tsv`, when it

- has no code;
- spans several translation units or modules (needs a multi-unit test kind);
- uses draft notation that is not C++ (placeholders, `cv`, `opt`, math);
- is ill-formed, no diagnostic required, so no verdict can be tested;
- puts an error annotation on a comment-only line, or includes a file it does not provide;
- is a fragment: both oracles report errors that an incomplete example produces (undeclared
  names, statements at namespace scope, missing files) on lines the draft does not mark as errors.

The fragment rule is the only one that needs the oracles. Its reason quotes the first error, so a
wrong call can be checked.

## Oracle disagreements

Where Clang or GCC disagrees with the draft, the test gets `// XFAIL: clang` or `// XFAIL: gcc`,
so `tools/test --cxx clang draft` and `--cxx gcc draft` pass, and the row in
`DISAGREEMENTS.md` says how. Rows are triage input, not verdicts. The cause can be a compiler bug,
a missing feature (Clang 23 has no reflection and no `<meta>`), an open CWG issue, an example the
draft got wrong, or an error the compilers report on another line than the one the draft annotates.
ycxx follows the draft. A test whose expectation is shown to be wrong is fixed in the extractor,
or reported upstream to the draft, never patched here.

## Regenerating

```sh
tools/draft-examples                      # from the pins and the recorded oracle verdicts; no compilers needed
tools/draft-examples --oracles            # rerun Clang 23 and GCC 16 too (about 10 s)
tools/draft-examples --pin-draft SHA --pin-cwg SHA --oracles   # move the pins
```

CI checks both on macOS whenever this suite, the extractor or the driver changes
(`.github/workflows/oracles.yml`): the regeneration must leave `tests/draft` unchanged, and the
suite must pass with `--cxx clang` and `--cxx gcc`. A newer Clang or GCC there (a Homebrew GCC
update) shows up as a diff; rerun `--oracles` locally with the same compilers and commit. Only
macOS: Clang on Linux uses libstdc++, so its header-dependent verdicts differ from the recorded ones.

Sources are downloaded once into `build/spec-cache`. Moving the draft pin renumbers examples
whose subclause gained or lost one. The test identities change, and so do their state and history.
